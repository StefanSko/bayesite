Bayesite · Investigation vertical slice

From saved computation to a continuable investigation.

Five connected steps turn one Bayesian run into an inspectable, immutable, replayable, forkable, and safely viewable research object—without putting Python, a package manager, or arbitrary code on the recipient path.

00
Recipient protocol

Define failure before implementation.

The frozen protocol changes the work from “build some investigation features” into a falsifiable handoff experiment.

Conceptual achievement

  • A fresh recipient must explain the question, estimand, effective model, and retained limitation.
  • They must verify and replay before changing one scientifically meaningful assumption.
  • Old evidence must become historical before replacement evidence exists.
  • An inconclusive continuation remains a valid result.

Technical contract

examples/investigation-counts/PROTOCOL.md

FAIL if:
  help is required but unpublished
  old evidence appears current
  source bytes change
  incomplete/failed work looks complete
  continuation loses provenance
Why it matters: implementation cannot redefine success after seeing what is easy to build.

Conceptual achievement

  • Estimand: mean_daily_count, not a maximum or staffing policy.

02
Snapshot and content-addressed storage

Identity belongs to exact bytes.

The snapshot is an immutable manifest plus a flat SHA-256 object store. Received bytes are hashed directly; canonical reserialization is never substituted for identity.

Artifact identitysha256(raw bytes)Model, data, fit, report, engine, citation.
Recipe identitysha256(framed inputs)Operation + separate model/data/fit + engine + target/profile + normalized settings.
Snapshot identitysha256(domain || manifest bytes)Exact manifest encoding is part of the durable object.

Honest state transitions

  • An attempt is persisted as incomplete before numerical work.
  • A typed runtime error becomes failed; it does not replace valid evidence.
  • The first current result for an operation is selected; later results remain unselected.
  • Conflicting current fits block inspection and downstream execution.
  • Changing execution inputs changes recipe identity and makes inherited selections historical.

04
Static viewer and fresh-recipient handoff

Evidence first; execution stays inert.

The browser reads the same snapshot contract as the CLI. It never samples, executes a bundled binary, imports a framework, or follows snapshot-controlled URLs.

What the vertical slice proves

A recipient can inspect, verify, replay, branch, and publish—while the original remains unchanged.

  • Effective runtime model is saved as evidence.
  • Model and data are independently identified.
  • Settings, seed, target, profile, engine, and upstream fit enter recipe identity.
  • Scientific reasons retain exact cited bytes.
  • Old results become historical on meaningful change.
  • Failures and incomplete work remain first-class facts.
  • Continuation lineage is recursive and locally verifiable.
  • The recipient path remains one Bayesite binary.

Deliberately still out of scope

Signatures, private-data publication, hostile multi-user filesystems, remote stores, generic schedulers, arbitrary-code recipes, merge semantics, browser sampling, and cross-target numerical equivalence.

Those are explicit boundaries—not accidental promises.
